# Writing Rig .QCs

In the ReSource paradigm, armatures are essentially models with no vertices. 

Therefore, their .SMD / .DMX files:

- Do not contain vertex data
- Do not contain a UV map
- Contain data regarding which bones are present in the armature and which bones they are parented to
- Contain animation data for a single frame (bone positions for the neutral stance / rest pose at frame 0)
- Only contain deformation bones (no controller bones)

# Rig .QC commands

All of the .QC commands in the Animation .QC article are essential for Rig .QCs, because all animations / animation sequences must be associated with a rig. Animations require a rig in order to be able to function.
Aside from that, other important Rig .QC commands are the following:

```
$modelname "animrig/path/to/rig.rrig" // for Apex Legends
```

The $modelname command specifies what the compiled output (produced by studiomdl.exe with the .QC as its input) should be named.

Examples:

```
$modelname "animrig/humans/class/medium/pilot_medium_bloodhound.rrig" // With Apex Legends, Respawn introduced a dedicated RTech file format for armatures: .RRIG, used alongside .RMDL models and .RSEQ animation sequences

$modelname "weapons/vinson/ptpov_vinson.mdl" // Valve MDLs can contain only vertex data, only animation data or both; Neither Titanfall nor Titanfall 2 uses a special format for armatures, so the bone data is simply included in the MDL
```


```
$definebone BoneName ParentName X Y Z XRotation YRotation ZRotation
```

Example:

```
$definebone "jx_c_delta" "" 0.000000 0.000000 0.000000 0.000000 0.000000 0.000000
$definebone "jx_c_start" "jx_c_delta" 0.000000 0.000000 0.000000 0.000000 0.000000 0.000000
$definebone "jx_c_pov" "jx_c_delta" 0.000000 62.992001 0.000000 0.000000 0.000000 0.000000
$definebone "jx_c_camera" "jx_c_pov" 0.000000 0.000000 0.000000 0.000000 0.000000 0.000000
$definebone "def_c_hip" "jx_c_delta" 0.000000 39.369999 0.000000 0.000000 0.000000 0.000000
```

$definebone lines are not meant to be written manually, but instead generated by studiomdl.exe, which Crowbar is a GUI for. To generate $definebone lines with Crowbar, you must Compile the MDL with your .QC input once, with "DefineBones" checked. If "Write QCI file" is not checked, then studiomdl.exe will only print out the $definebone lines but not write anything. If "Write QCI file" is checked, the $definebone lines will be written to a .QCI file which can then be included in the main .QC with $include DefineBones.qci or by manually copying the lines and pasting them in the main .QC file.

In certain cases, especially concerning custom armatures, it is possible that studiomdl.exe may not be able to read the bone data and output the necessary $definebone lines. In these cases, you can either write the $definebones lines manually using the information in the armature .SMD (all necessary information is present: bone name, bone parent name, coordinates), you can write a script to do it, or you can Compile with the $includemodel command and the model file for the mesh you want to associate the armature with.

```
$weightlist WeightlistName {
    BoneName1 weight1
    BoneName2 weight2
    , etc. ...
}
```

The $weightlist command creates a discrete list of bone weights to dictate which bones are affected by a certain animation sequence. This can be used, for example, to separate the upper body and the lower body on a character model and play different animation on each segment. Weights usually take valuies from 0 to 1, where 0 means the bone is completely unaffected (not animated) and 1 means the bone is fully influenced by the animation (the animation plays to its maximum extent). The value can exceed 1, at which point the intensity of the animation follows the same behavior, multiplying the intensity of the animation on the bone(s).

$defaultweightlist sets the default weightlist if a weightlist is not specified in an animation sequence.

Weightlists can be used for an animation sequence by mentioning them in either the $animation or the $sequence:

```
$animation "wind_loop_anim_layer" "ptpov_vinson_anims\wind_loop_anim_layer.smd" {
	fps 30
	loop
	weightlist "weights_wind_loop_layer"
}

$sequence "wind_loop_layer" {
	"wind_loop_anim_layer"
	fadein 0.2
	fadeout 0.2
	realtime
	fps 30
	loop
	weightlist "weights_wind_loop_layer"
}
```

Respawn often use weightlists for weapon and character models to isolate certain areas they want animation sequences to play on separately.
