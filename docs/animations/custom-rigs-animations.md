
# Creating Custom Rigs and Animations for Modded Apex


## Prerequisites

- Blender - https://www.blender.org/ or the Steam Store
- Blender Source Tools plugin for Blender - https://developer.valvesoftware.com/wiki/Blender_Source_Tools
- RSX (ReSource eXtractor) - https://github.com/r-ex/rsx
- Crowbar - https://steamcommunity.com/groups/CrowbarTool
- RePak - https://github.com/r-ex/RePak
- SFM, Portal 2 or a Source game with studiomdl.exe older than Portal 2
- A text editor, preferably Visual Studio Code or Notepad++

This guide will not teach you how to install and set up these tools.

READ EVERYTHING OR ELSE YOU MAY HAVE VERY FRUSTRATING PROBLEMS DOWN THE LINE AND WASTE TIME!

## Creating compatible rigs in Blender and exporting them 

- To ensure compatibility with the bones in the game engine you **MUST** import and use the in-engine deformation bones OR create a custom deformation bone rig following the exact same principles as Respawn (same bone naming, same bone orientation, same bone configuration, etc.). The easier option is using one of Respawn's deformation rigs.
- Source has a bone system where the tail of the bone is in-world axis aligned none of the bones are connected at the tail or head (freely floating joint system). In order to access constraints like ChildOf and Inverse Kinematics, you **MUST** create a separate rig which includes bones that are named the same as the deformation bones **AND** extra controller bones. This second armature will be used to control the deformation bones of the in-engine armature through ChildOf constraints, which means that you must add a ChildOf constraint to every single in-engine deformation bone, parenting it to its corresponding bone in the second armature with controller bones, i.e.: def_l_shoulder from the in-engine armature would be parented to the def_l_shoulder bone in the second armature with controller bones using the ChildOf constraint. This is the most tedious part of the process, unless automated using scripts.
- All the bones in the in-engine armature MUST be unparented for the inverse kinematics in the controller bone rig to work correctly, therefore you must modify the in-engine armature to have a flat / horizontal hierarchy (no parent-child relationships)! You can do this by selecting all the bones in the armature in edit mode then pressing ALT + P to unparent all bones.
- Any Respawn human rig exported from the game's RPAKs with RSX and imported into Blender with Blender Source Tools can be aligned to function with the custom rig given out in this guide by rotating the shoulders 45 degrees on Y and the elbows 42 degrees on Z, to create a T-Pose. After you have rotated the bones, go to the Modifiers section of your character mesh and Apply the Armature modifier. Afterwards, select your rig in object mode, go to pose mode, select all bones with A and Apply Pose As Rest Pose with CTRL+A, then go to object mode, deselect everything, select the mesh, add the in-engine Armature to the selection by holding SHIFT and selecting and then press CTRL + P to parent the mesh to the Armature object With Armature Deform (the simplest option, no automatic weights or anything). The neutral pose of the in-engine Armature will now be a variation of the T-Pose. Make sure to reset all the transforms on all the bones by selecting all of them with A and pressing CTRL + G, CTRL + R then CTRL + S.
- Some characters may have extra bones that you will need to include if you wish to ensure full compatibility with those character models. A good example is Gibraltar, with his Gunshield. "Compatibility" here refers to having the option to animate all the bones supported by the Vertex Groups of the mesh you want to animate and ensuring that there are no visual glitches or unintended deformations.
- The rig provided with the guide supports Inverse Kinematics for the arms and legs and has FK - IK switches in the Custom Properties section of the Armature.
- Respawn developers create all their rigs in Maya and also animate in Maya, which has Y as its up axis. It's possible to align a custom rig you created with the XY plane, facing +Z and get correct bone orientations. Afterwards, the armature can be parented to an Empty object or any other object to feign orientation with Z as the up-axis and ease posing and animation. 
- In order to ensure proper functionality of exported rigs (correct compilation, correct importing), the armature must have NO bone constraints, NO modifiers and must be positioned neutrally, so that it lays flat on the XY plane in Edit Mode, with all bone tails pointing towards +Y and the root bone (jx_c_delta) at the world origin. The orientation of bones in Blender is ALWAYS towards +Y, bone axes cannot be modified like in Maya! If you want to be safe, you should also parent the bones in the same hierarchy as Respawn. Using a Respawn deformation bone rig as a reference, Blender's Outliner and with a little bit of practice, this should not take longer than 5 - 10 minutes (in the Outliner, select all the bones you want to parent, select the bone you want to be the parent last, move your cursor to the 3D view, press P, Maintain Offset). Applying all bone constraints in the rest pose (so that the bones in the deformation bone rig retain the neutral position you set up for the controller bone rig) and reparenting all bones MUST be done AFTER baking your animations. The IK controller bones cannot function correctly without the horizontal hierarchy.
- After you have finished setting up the deformation bone rig correctly, it is now possible to export it with Blender Source Tools: go to Scene, expand "Source Engine Exports" & "Source Engine Exportables", move your armature in Object Mode to a collection with a name of your choosing, in the "Source Engine Exportables" deselect all other collections except for the collection with your armature, scroll down to the contents of the collection in "Source Engine Exportables" and make sure the armature is selected (it will have an armature specific icon). You can now go to "Source Engine Exports" and export your armature as an SMD or DMX. If you choose SMD (the default, human-readable format), you don't have to do anything extra. If you choose DMX (binary format, non-human-readable), you need at least DMX Model Version 18, Binary 3 (Portal 2).



## Creating animations

- Make your animation IN THE ACTION EDITOR! Select your Armature from the dropdownc if it isn't already selected, assign it a Fake User with the Shield button, then Duplicate the KeyingSet action already included with the resources. Name your new action to whatever you want the animation to be. ONLY use the Non-Linear Animation Editor (NLA) if you are an ADVANCED user of Blender and know what you're doing! You should know, however, that blend layer modding is currently broken and not supported in modded Apex, so your mileage may vary. Your layer blending may work, but do not expect it to work.
- You only need to key every single keyframe on your controller bone rig and not on the in-engine armature as well (go on every frame, select all the bones with A, press K, keyframe whole character, selected bones only). After keying your animation, you should be able to uncheck "Lock Object Modes" in Edit, select the controller bone rig, go into Pose Mode, select the deformation bone rig, also go into Pose Mode on it, press play (SPACEBAR by default) and the animation will play on the controller bone armature while you have the deformation bone armature selected. Blender will now allow you to bake the animation on the in-engine deformation bone rig.
- Bake the animation ON THE IN-ENGINE RIG with parenting, constraints, visual keying. One way to do this is by going into selecting the custom rig, going into Pose Mode, making sure Lock Object Modes is disabled in the Edit menu, selecting the in-engine rig, going into Pose mode, making sure you have a new action with a name that satisfies you, selecting all bones with A, going into the Pose menu, going into the Animation submenu and then clicking on "Bake action...". DO NOT modify other settings in this dialogue unless you know what you're doing!
- First person (viewmodel) and third person (worldmodel) animations require different treaments:
- For exporting baked first person animations, the camera bone must always be at the world origin in Blender when ready for being exported using the Blender Source Tools (offset the IN-ENGINE armature by going into the Edit menu, enabling Lock Object Modes, selecting your in-engine armature in OBJECT mode, pressing G, Z twice, then typing in -63 to offset it by -63 units on Z **AFTER** baking, then APPLY THE TRANSFORMS to the rig with CTRL + A and selecting "All Transforms", so as to not mess up the animation). If you want to skip this step, you will have to animate with the offset applied from the beginning.
- For exporting baked third person third person animations, the root bone (jx_c_delta for Respawn) must always be at the world origin
- Using the Blender Source Tools plugin, go to Scene -> Source Engine Export, pick an export path and export as .SMD (.DMX is possible as well, however it is a binary format instead of a plaintext format) with Z as the Target Up Axis and Source as the Target Engine. This step is basically the same as for the armature.

## Preparing the rigs and animations for importing into the ReSource engine

- You must have a .QC file to compile your rig and animations into a binary format (.MDL V49) using studiomdl.exe (Valve's model compilation tool. Rigs are technically models without polygons and Valve models can be animation-only). If you set up RSX to export .SMDs, it will export very useful .QCs as well, which you can use as your foundation. Alternatively, you can make your own
- In the .QC, define your raw .SMD animations exported from blender using $animation, before defining any $sequences (otherwise they will not be usable in animation sequences). After defining your animations, you can now use them in $sequences.
- In the .QC, alongside $definebones, you can also define $attachments for purposes such as attaching particle effects.
- Inside $sequences, you can set up audio **EVENTS** (an audio clip is NOT the same as an audio EVENT) to be called, you can set up animation events, activities, activity modifiers, particle effects, VScript callbacks (both client and server). Animation layer blending is broken.
- IF YOU ARE USING A CUSTOM RIG AND NOT AN ALREADY EXISTING RESPAWN ONE (new bones, missing bones, different bone names, different bone positions, etc.): You can either manually define every single bone (which is extremely tedious) using the raw source SMD file ($definebone [name of bone] [parent of bone] [coord1] [coord2] [coord3] [coord4] [coord5] [coord6]) OR use $includemodel to include the raw data of the model you're trying to make animations for, so that studiomdl.exe (or Crowbar, a GUI interface for studiomdl.exe) can automatically define the bones (without this, it's very likely that studiomdl.exe won't be able to detect and write the bone data). In Crowbar, you have to go to the Compile section, select your .QC, check "DefineBones" and "Write QCI file", then compile, to print out the bone definitions to an external .QCI file in the same folder. You can then $include the .QCI file manually with $include "DefineBones.qci" at the top of the .QC (or check include QCI) or copy the $definebone lines and paste them above the $animations in your main .QC file.
- It's recommended to use either Portal 2 or Source Filmmaker studiomdl.exe (Source Filmmaker is free and its studiomdl is newer). Alternatively, you could use a custom version like nekomdl, with varying results.
- Go into Crowbar, select your .QC and Compile. 
- The resulting output will be a v49 .MDL file (Valve model) which you must then convert to a .RRIG and .RSEQs using R5-AnimConv by SomeoneAteMyLastSliceOfPizza (SAMLSOP). Depending on the version of modded Apex, you will have to convert them to Season 3 or Season 21 .RRIGs and .RSEQs. The input for R5-AnimConv MUST be a v49 .MDL, older versions of .MDL are not accepted.
- It is necessary to include the RRIG in your .QC, even if you only want to add custom RSEQs, because all animation sequences need to be associated with a rig (even if they're meant as shared libraries for multiple models). For most purposes it is enough to include the RRIG made by Respawn which you have already exported using RSX, UNLESS you modified the base deformation bone, in-engine armature!

## Importing your assets into the ReSource engine

It is necessary to have knowledge of how to use RePak for this section

- In your assets folder for RePak, you must have an asset other than the .RRIG and .RSEQs, otherwise the animation sequences won't play in game (bug). A simple texture is recommended, which must be placed above any .RRIGs or .RSEQs in the JSON manifest for RePak.
- In your JSON manifest for RePak you must add a line "buildDate: 4004773717" (idk for s21 version). RPAK assets are loaded in the order of creation of the RPAKs, not in the order that the RPAKs are loaded, therefore assets from core RPAKs distributed with the modded version of Apex you installed may override your rigs and animations, if you're animating for already existing assets with rigs and animations.
- Pack the assets into an RPAK and load it like any other mod (mods -> your mod -> paks -> Win64 / Win64_server. Include the RPAK in preload.rson, otherwise it will not be loaded in-game. Your mod must also have a .VDF file with basic information about the mod). This guide is not meant to teach how to create and load mods. For more information, refer to the guide for creating mods.
- You do not need to include the model if you're only planning on adding custom animations and / or custom rigs.
- Extra information: when playing any animation sequence (RSEQ - Respawn animation SEQuence), the engine will search for the RRIG it is parented to / associated with in its RPAK and apply it on the mesh the animation is meant to be played on. Therefore, it is technically possible to play any animation on any mesh (albeit with very different results depending on the mesh and rig). If the mesh does not have any Vertex Groups assigned to be deformed by bones on the RRIG, the animation on those bones will simply be ignored, therefore it's possible to play Nemesis RSEQs with the Nemesis RRIG on an Alternator mesh and the animation on bones such as the magnet latches on the Nemesis' barrel will be ignored, because the Vertex Groups for those Nemesis magnet latches do not exist on the Alternator meshes, which means they will have no influence on the way the meshes are deformed. HOWEVER, it is possible to trigger fatal errors (game crashes) if, inside of an RPAK, an RSEQ is associated with an incompatible RRIG. For example, it is not possible to play an Alternator RSEQ on a HAVOC RRIG. Hence, it is important to be very careful which RSEQs you associated with which RRIGs when you are using RePak to pack RPAK archives.

## Limitations

Disclaimer: this list is not perfect and there may be workarounds that are yet to be discovered. If you manage to find workarounds / fixes, please share with the community!

- Currently there is no way to create proper layered animations (lack of tools emulating what Respawn does in-house), hence importing a custom rig with custom animations will partially break animation layering on meshes that have them (animations playing when they're not supposed to). All the animation sequences will be present and animation behavior will be correct in large part, but, for example, idle animations, mid-air layers, etc. may get buggy. Concretely, for the Smart Pistol: shooting, reloading, aiming down sights, inspecting, etc. will work correctly, but the idle, sliding, etc. animations are very buggy
- Any custom rig you use MUST include essentially all the bones present in the in-engine rig so as to prevent visual issues like unwanted stretching of meshes. If you are not using a modified deformation bone rig, the animations will be fine, however you will not have any control over the bones which are not included. If you are using a modified deformation bone rig, there will be extreme distortions in the mesh if you do not include all the necessary bones because the deformation rig MUST have a flat bone hierarchy for the controller bones to work when animating. To solve this issue, you must either reparent all bones like they are by default, which will not guarantee a fix for all bones because some may be missing, or you must include all the bones expected by the mesh you are working with (highly dependent on the mesh and its Vertex Groups, which you can see in Blender).
- If the mesh does not have a pre-existing rig (new custom prop / model, etc.), then you must either use a pre-existing in-engine rig made by Respawn or create a rig with an identical bone setup (same orientations, etc.). The easier option is to use a pre-existing Respawn rig exported from the game's assets. If the bones do not have the same orientations, then the rig will be completely broken in-game, resulting in extreme twisting and distortion of the mesh.
- Custom NPC / 3rd person legend animations lack extra data used by the game to adjust behavior, so do not expect perfect functionality and compatibility
